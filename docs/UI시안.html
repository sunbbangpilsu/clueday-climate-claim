화면 구성과 사용 흐름

현재 동작하는 모바일 웹의 서로 다른 6개 화면을 390px 폭의 모바일 뷰포트 기준으로 기록했습니다. 일부 화면은 입력 영역·결과·요약서를 보여주기 위해 스크롤한 상태입니다. 모든 인물·진료 사례는 가상이며 실제 청구·지급 결과가 아닙니다.

화면 경로 핵심 상호작용
01 홈 #home 현재 지원 범위 확인, 보장 입력·카드로 이동
02 진료 카드 #card 빈 양식에서 직접 입력·확인 후 카드 생성
03 보장 입력 #check 대상·진료 건 선택, 보장 조건 입력
04 결과 #result 예상액·대기 항목·서류 체크 확인
05 준비 요약서 #claim 작성 보조 문서 인쇄, 공식 접수 단계 확인
06 가족 관리 #family 가족 추가·선택, 기록 분리

기본 흐름: 홈 → 보장 입력 → 결과 → 준비 요약서 → 공식 접수 채널.

보호자 흐름: 가족 관리 → 가족 선택 → 진료 건 선택/새 건 → 보장 입력.

공통 설계

  • 기본 본문 17px, 제목 24px, 큰 누름 영역과 하단 4개 메뉴.
  • 초록색을 주요 행동에 사용하고 예상·미확인·가상 사례를 텍스트로 함께 구분.
  • 입력은 라벨과 연결하고 키보드 포커스를 표시. 밝은/어두운 시스템 테마 지원.
  • 일반 입력과 가상 시연을 분리하고, 아직 없는 자동 알림·OCR을 작동 버튼처럼 표시하지 않음.
  • 320px·390px·큰 화면에서 주요 화면 배치 확인. 화면 캡처는 다크 테마 기준.

01. 홈 - 시작과 지원 범위

사용자 목표

어떤 도움을 받을 수 있는지와 현재 지원 범위를 이해하고 작업을 시작한다.

주요 요소

  • 지역 선택과 서비스 설명
  • 시연·개발 예정 기능 안내
  • 실제 특보 확인 필요 표시
  • 보장 확인 / 진료 카드 행동 버튼
  • 공식 접수까지의 단계

전환

보장 확인 → #check
진료 카드 → #card
가상 시연 → ?demo=1#result

예외·상태

샘플에 자료가 없다고 '특보 없음'으로 단정하지 않는다. 연결 오류는 재시도 안내로 표시한다.

구현 연결

GET /api/alerts

캡처: 가상 시연 모드의 홈. 개인 기록과 분리된 예시다.

02. 진료 카드 - 직접 확인한 상황 전달

사용자 목표

실제로 경험한 환경·활동·노출 시간·증상을 정리해 진료 시 보여준다.

입력과 행동

  • 환경 선택, 활동·시간 입력 필수
  • 증상은 선택 입력
  • 입력 내용을 확인한 뒤 생성

안전한 초기 상태

날씨·활동·시간·증상을 미리 채우지 않는다. 입력 전에는 '작성된 카드 없음' 상태다.

결과·수정

생성하면 입력한 문구와 서류 발급 요청을 카드로 표시한다. 내용을 바꾸면 이전 카드를 무효화한다.

구현 연결

POST /api/doctor-card

특보 발령이나 질병을 자동 판단하지 않으며, 특정 진단코드를 요구하지 않는다.

03. 보장 입력 - 진료 조건과 가족 구분

사용자 목표

누구의 어떤 진료인지 구분하고 진단서·사고의 실제 조건을 입력한다.

구성

  • 상단: 사람·진료 건 선택 / 새 진료 건
  • 날짜·사고 지역·가입 대상 확인
  • 질병코드·감염병 선택
  • 기지급·응급실·입원·취약계층 조건
  • 펼침 영역: 상해 주수·관련성·유족 청구

검증과 피드백

일반 모드 미래 날짜와 잘못된 코드 형식은 거부한다. 제출 중에는 중복 요청을 막고 오류 이유를 표시한다.

전환·상태

확인하기 → #result
입력 변경 → 이전 결과 무효화

구현 연결

GET /api/coverages
POST /api/eligibility

캡처: 입력 영역의 스크롤 상태. OCR은 개발 예정이며 현재 직접 입력한다.

04. 결과 - 예상 합계와 확인 대기

사용자 목표

계산 가능한 항목과 확인이 더 필요한 항목을 구분하고 준비 서류를 기록한다.

결과 상태

  • 예상 항목과 근거·합계
  • 확인 대기: 합계에서 제외
  • 조건 변경 후 재확인 필요
  • 계산상 청구 기한 표시
  • 진료 건별 서류 체크

가상 47만 원의 조건

샘플 한파, 가입 대상·취약계층인 72세 가상 어머니, T68, 응급실, 입원 2일, 별도 통원 1회.

15만 + 10만 + 20만 + 2만 = 47만 원. 증빙·병급이 검증된 실제 지급 확정액이 아니다.

전환

가입 조건 확인 후 요약서 → #claim
조건 수정 → #check

캡처: 결과 영역 스크롤 상태. 일반 모드의 특보 의존 항목은 실제 자료 연동 전 확인 대기로 남긴다.

05. 준비 요약서 - 공식 접수와 구분

사용자 목표

작성 내용을 정리하고, 공식 접수까지 남은 작업을 확인한다.

주요 요소

  • 상단: 청구인·연락처·계좌 선택 입력
  • 사람·진료 건에 연결된 요약 표
  • 예상 합계와 확인 대기 항목
  • 인쇄 / PDF 저장
  • 공식 양식·증빙·접수 안내

접수 범위

요약서는 공식 보험금청구서를 대체하지 않는다. 공식 청구서·동의서의 작성과 서명, 증빙 준비, 보험사 접수가 별도다.

데이터 경계

청구인·연락처·계좌는 이 브라우저의 해당 진료 건에만 보관한다. 시연 모드는 저장하지 않는다.

구현 연결

GET /api/claim-channels
브라우저 인쇄 기능

캡처: 요약서·공식 절차를 보여주는 하단 스크롤 상태. 실제 보험사 접수는 수행하지 않았다.

06. 가족 관리 - 사람과 진료 건의 분리

사용자 목표

가족을 등록하고 해당 가족의 청구 준비를 독립적으로 관리한다.

입력과 전환

  • 호칭·사는 시군 필수
  • 나이·취약계층 여부 입력
  • 가족 선택 → 그 사람의 #check
  • 같은 사람도 새 진료 건 생성 가능

분리 원칙

질병코드·결과·서류 체크·청구인·계좌는 사람과 진료 건별로 분리한다. 다른 사람에게 이전 입력이 따라가지 않는다.

초기·예정 상태

일반 모드 처음 사용 시 등록된 가족이 없다. 자동 특보 알림은 개발 예정으로 안내하며 작동 스위치를 제공하지 않는다.

검증

상태 분리 테스트 7개와 브라우저 전환 확인. 실제 대리 청구에는 보험사 위임 절차가 필요하다.

캡처의 '가상 어머니'는 시연용 인물이며 일반 모드에 자동 등록되지 않는다.
